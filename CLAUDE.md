# CLAUDE.md

This file is public: it is a contributor and AI-agent guide. Do not put secrets,
billing details, hostnames or owner-only operational notes here. Those live in
`CLAUDE.local.md` (git-ignored) or outside the repository.

Averyn (codename): open-source, self-hostable sports-tracking platform. iOS +
Android + Web. Pre-alpha. The code of MVP-1, of most of MVP-2 and of the launch
slices is in place, but **the real-device campaign is the open gate**: the
[device matrix](docs/testing/device-matrix.md) is empty, and no feature is "done"
until the row of the matrix that covers it is green. The current target is
**MVP-L, a free, privacy-first public launch built around three moments
(recording, summary, history)** ([ADR-0028](docs/adr/0028-consumer-launch-target.md);
no fixed date, one developer, with a cut line): the live checklist is
`docs/product/mvp-launch.md`. Order of work: campaign and fixes first, then the
experience, then the new features. Read `docs/README.md` for the docs system,
`docs/product/roadmap.md` for scope, `docs/design/TDD-0001-tracking-engine.md`
for the tracking engine and `docs/adr/0026-averyn-synapse-link.md` for the
Synapse link.

## Layout

- `shared/{domain,tracking,metrics,analysis,sensors,sync,api,client}`: Kotlin
  Multiplatform (jvm, android, iOS). Pure Kotlin, no platform deps.
  `shared/analysis` holds the analysis of an activity (splits, elevation,
  series, best efforts); `shared/sensors` holds the heart-rate frame parser and
  its metric. `shared/api` holds the contract of the endpoints (DTOs only);
  `shared/client` holds the read path of the apps (Ktor client, the copy of the
  server on the device, the merge of the history). `shared/ios-umbrella`
  re-exports them as the `Shared` framework.
- `backend/`: Ktor modular monolith, one Gradle module, package per domain under
  `dev.averyn.backend`. Flyway SQL in `src/main/resources/db/migration`.
- `apps/android` (Compose), `apps/ios` (SwiftUI, project generated by XcodeGen),
  `apps/web` (React + TS + Vite).
- `build-logic/`: convention plugins (`averyn.kmp-library`, `averyn.ktlint`).
  Versions only in `gradle/libs.versions.toml`.
- `tests/gps-fixtures/`: reference traces + expected results.
  `tools/campaign/`: reads a diagnostics export and prints a matrix row.
  `infrastructure/compose/`: local/self-host stack.

## Commands

```sh
./gradlew check                                   # tests + ktlint, all modules
./gradlew :shared:domain:jvmTest :shared:metrics:jvmTest :backend:test
./gradlew ktlintFormat
./gradlew :apps:android:assembleDebug
(cd apps/web && npm run check && npm run build)   # lint (oxlint) + typecheck + vitest
cd infrastructure/compose && sh init-env.sh && docker compose --env-file .env up -d --build
```

iOS cannot be built on Windows: build it on macOS following
`apps/ios/README.md`. The Docker backend build sets `AVERYN_BACKEND_ONLY=1` so
Gradle skips Android/iOS modules.

## Rules that matter

- Raw location samples are immutable; filtering only flags. No silent data loss;
  every drop is counted with a reason.
- Metrics are versioned (`algorithm_version`); a behavior change = new version +
  `docs/metrics/*.md` update. Never edit an existing version.
- The state machine in `ActivityState` must match the diagram in TDD-0001;
  change both together.
- Never log coordinates, tokens or user content. Private by default. See
  `docs/privacy/data-classification.md`.
- Hard-to-reverse decisions need an ADR (`docs/adr/`); accepted ADRs are
  immutable (supersede instead).
- PR titles: Conventional Commits. Tests ship with logic. No secrets in the repo.
- Commit identity: noreply email only, never a real address, in commit metadata
  or `Co-authored-by` trailers. Enable the guard rail with
  `git config core.hooksPath .githooks`.
- Brand neutrality: no competitor names, no disparagement of any product or
  company, anywhere in the repo. Describe the market and prior art generically.
  Naming an interoperability format (GPX, FIT, TCX, HealthKit, Health Connect,
  Bluetooth GATT profiles) is fine where it is technically required.
- Don't scaffold ahead: later areas (social, segments, watch, offline maps) get
  code only when their milestone starts. No code without an issue in the current
  milestone; a spec without code and tests in the same increment stays `draft`.
- Accepted ADRs take editorial edits only (typo, link, translation, brand
  redaction), noted at the bottom with the date. Language of docs, code and
  commit messages: English.
- Third-party sensor ecosystems are optional integrations, never a dependency of
  a core feature: see [ADR-0010](docs/adr/0010-ecosystem-boundary.md) and
  [ADR-0014](docs/adr/0014-sensor-integration-contract.md).
- HRV/ECG/sleep/stress-adjacent data is a special data class (health), with its
  own consent-per-scope and DPIA-before-launch rule: see
  [ADR-0013](docs/adr/0013-health-data-special-category.md).

## CI gate

**Woodpecker is the gate** (`.woodpecker/ci.yml`): JVM, backend, Android, web,
docs, link check, OpenAPI lint and secret scan. A change is merge-ready when
that pipeline is green on the final tree.

- **Local, no server:** `tools/ci/ci-local.sh` from the repo root (Docker
  running). It copies the working tree to a temporary directory and runs
  `woodpecker-cli exec`, so the checkout is never modified.
- **Server:** once the Woodpecker server is connected, push the branch and the
  check is `ci/woodpecker/push/ci` (or the `pull_request` context);
  `gh pr checks <n> --watch` shows it. The server is not connected today, so the
  local run is the gate until the owner wires it and makes the check required.
- **Not covered by CI:** iOS (needs macOS), the compose smoke tests (need
  docker-in-docker) and the signed-in round trip. Build iOS on macOS and say so
  in the PR; a Swift change that has not been compiled stays a draft.
- A red gate on `main` stops everything. Fix it before new work.
- A feature is `verified` only when its device-matrix row is green.
