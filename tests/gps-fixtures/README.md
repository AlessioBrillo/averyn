# GPS fixtures

Reference traces with expected results. Tracking, quality and metric code is tested against these ([TDD-0001 §6](../../docs/design/TDD-0001-tracking-engine.md)).

## Format

One directory per fixture:

```text
<fixture-name>/
  track.gpx        # the input (GPX 1.1); real recordings must be anonymized/shifted before commit
  expected.json    # description, algorithm versions, expected metrics with tolerances, expected quality flags
```

`expected.json` values are pinned to an `algorithm_versions` entry; changing an algorithm means a new version and a new expected block, never editing the old one.

## Rules

- **Never commit real personal traces** (home/work locations). Anonymize by translating to a different area and shifting timestamps; keep the noise characteristics.
- Prefer small files; long activities are generated by script, not stored.
- Each fixture states what it exercises (see the list in TDD-0001 §6).
